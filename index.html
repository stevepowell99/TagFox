    Eight things worth knowing before you dig in:
    
              
      
                
    1. 
                  Tag Fox is a fast front-end for Voidtools Everything over HTTP. Without Everything’s HTTP server running and the right base URL in Settings, the list stays empty.
                
      2. 
                
    2. 
                  The current folder (breadcrumb under Favourites) is where search, paste, new folder, and “Add TODO” anchor. Empty scope searches the whole index.
                
      3. 
                
    3. 
                  Tree view (sitemap icon) shows folder structure in the Name column (path sort) and hides the Path column; with an empty query and no tag filters, files in subfolders stay out of the list until you open those folders. Turn it off for a flat list with a visible Path column.
                
      4. 
                
    4. 
                  Tags live in filenames as [(t1,t2)] on the last segment, e.g. Notes[(draft)].md. They stay visible in Explorer, Drive, and zip exports.
                
      5. 
                
    5. 
                  Use favourite folders and saved searches (numbered chips, Ctrl+1…9) instead of tabs. Use the vertical Shelf to stage copies between locations.
                
      6. 
                
    6. 
                  The right Viewer previews many file types and edits folder docs / markdown; Google shortcuts open in an app child window, not always inline.
                
      7. 
                
    7. 
                  Cloud “streaming” (files that look local but fetch on demand) weakens some operations — see Gotchas.
                
      8. 
                
    8. Press F1 (or the ? button) anytime; this help remembers which tab you last opened.
      9. 
              
    
            
    
            
    
              
    
                When the web became searchable, it was surprising that the web could feel faster than your own disk. Local search is still slow unless you use an index tool like Everything.
              
    
              
    
                Search boxes (and Drive) train us to type a word and expect the right thing — but you usually get a flat list. Complex projects have similar folder names; it is easy to lose the map of what belongs where. Folders are not an end in themselves, yet real work still arrives as trees: zips, phased folders, “here are the sources”.
              
    
              
    
                Many desktop file browsers are sluggish; search there feels like a crawl. Tag Fox targets instant search with results still shown in context (folders, subfolders, tree-style order) so you can stay out of File Explorer for day-to-day navigation.
              
    
              
    
                The same need shows up in project management: past a few dozen tasks, flat lists fail; you want a tree and links between tasks and where files live. Tools like Trello or Workflowy add sideways links. Tag Fox keeps todos and notes on the filesystem (tags, small markdown files, folder docs) so search and project structure stay one place. Older apps such as TagSpaces pursue a similar idea but litter hidden metadata folders everywhere — Tag Fox keeps tags in the visible name.
              
    
              
    
                Tag Fox is intentionally simple: bracket tags, fast preview, keyboard workflow, favourites, and a shelf — not a full proprietary PM system.
              
    
            
    
            
    
              
      
                
    • Keyboard-first — navigation, bulk actions, tags, rename, history; see Shortcuts.
      • 
                
    • Favourite folders and saved searches (full snapshot: query, scope, tags, filters, Advanced, sort, tree view).
      • 
                
    • Search scope can include Drive folders shared with you that appear under your synced paths.
      • 
                
    • 
                  Fast previews for many Office types, PDF, images, text/json; PowerPoint via text-style preview where supported.
                
      • 
                
    • Add TODO — small markdown file in the current folder, default tag pattern for todos.
      • 
                
    • 
                  Folder doc — read/create readme.md, claude.md, agents.md, and other conventional explainer names; see Projects.
                
      • 
                
    • 
                  Besides Tree View, use flat, Everything-style lists — e.g. recency buttons (1h, 1d, 1w, …) for “what changed lately”.
                
      • 
                
    • 
                  No tabs / dual pane — use favourites + Shelf to copy between folders (visual staging, OS drag when needed).
                
      • 
                
    • 
                  Electron — straightforward to build and run, lightweight enough; some Explorer shell menu actions are missing and must be done manually if you need them.
                
      • 
                
    • 
                  Mixed local + Google Docs — office files preview inline; .gdoc / Workspace shortcuts open in a child window (faster than hunting the browser tab). Shared or streaming-only shortcuts may fail — see Gotchas.
                
      • 
              
    
            
    
            
    
              
    Current folder & query
    
              
      
                
    • The breadcrumb under Favourites is the current folder Everything scopes to (unless you clear scope for the whole index). The pen toggles a path editor; Enter saves, Esc cancels; invalid paths are rejected.
      • 
                
    • The search box filters what Everything returns. Results update as you type (debounced); Enter forces a refresh. Tip: !foo excludes matches for foo. Clear only clears query text.
      • 
                
    • 
                  Searches under the current folder are recursive (subfolders included). With tree view on, an empty query and no active tag filters use a tree-browse pattern: folders everywhere under scope, but files only in the current folder; type a query or turn tags on for one merged file+folder list. Tree view off shows a Path column and no synthetic folder rows; sort by any column.
                
      • 
                
    • 
                  Turning tree view on sets sort to Path A→Z and hides the Path column; turning it off shows Path again. “Special” paths (e.g. segments with ., ~, $) may appear dimmed but are not hidden from the list.
                
      • 
                
    • Recency filters limit to items modified in the last hour/day/week/month/year.
      • 
                
    • 
                  Search history — Alt+← / → or toolbar arrows — steps through full snapshots (query, folder, tags, options). Recent folders (Ctrl+L, clock) only jumps paths, not full snapshots.
                
      • 
              
    
              
    Advanced & sorting
    
              
      
                
    • Advanced (panel below the button): match case, match path, whole word, diacritics. Plain search supports | in Everything without a separate “regex” mode.
      • 
                
    • Header edges resize columns; header clicks sort by name, path, size, or modified (Everything name/path/size/date where applicable).
      • 
                
    • 
                  Settings (Ctrl+, / ⌘+,): Everything base URL, results per page (then Load more or scroll for the next page), HTTP user/password, auto-refresh timer, global show/hide shortcut, optional search debug log, open the Shelf staging folder in Explorer.
                
      • 
              
    
            
    
            
    
              
    Breadcrumb
    
              
      
                
    • Click a segment to set the current folder to that path.
      • 
                
    • 
                  ▾ between segments lists sibling folders; ▾ after the last lists children. Hover opens nested panels; → / ← move levels. Empty path in the path editor clears scope (whole index).
                
      • 
              
    
              
    Favourites & shelf
    
              
      
                
    • The diskette after folder chips saves the present current folder; chip × removes it.
      • 
                
    • 
                  The diskette after saved searches stores the same snapshot as search history. Chips show numbers; hover for the query; Ctrl+1…9 activates by slot.
                
      • 
                
    • 
                  Checkboxes drive bulk actions (Explorer copy, delete, tags). Ctrl+H bulk renames names with wildcards and live preview. Drag rows to folder rows or breadcrumb segments to move; Shift drop copies; Alt drag or Shelf “OS drag” starts real Explorer drags. The vertical Shelf follows the same rules for staging.
                
      • 
              
    
              
    Tags
    
              
      
                
    • The tag toolbar row starts with a tag icon (no “Tags:” label).
      • 
                
    • Bar filters are AND. ↻ at the end of the tag row re-queries and can prune ghost tag chips from the remembered list after a full [(…)] scan.
      • 
                
    • Plain [text] without parentheses is not a Tag Fox tag. Ctrl+T edits tags on the selection.
      • 
              
    
              
    Viewer & row menu
    
              
      
                
    • 
                  For a folder (or folder context with nothing else open), Folder doc picks the first of readme.md, readme.txt, claude.md, agents.md, about.md, about.txt, context.md, context.txt, index.md, index.txt (case-insensitive). If none exist, save creates readme.md.
                
      • 
                
    • .md / .txt files edit with preview; Google shortcuts may open in-app; PDF, images, JSON/text, many Office types preview. Very large files may skip preview.
      • 
                
    • The row ⋯ menu: copy variants (Explorer-ready, paths, URL), open, reveal, Drive helpers — same full-path copy as Ctrl+Shift+C on checked or highlighted rows.
      • 
              
    
            
    
            
    
              
    
                Tag Fox is meant to reduce the gap between where files live and what you need to do. Instead of a separate app for every outline, you keep lightweight notes and todos on disk next to the data.
              
    
              
      
                
    • 
                  Add TODO in the Viewer creates Title[(TODO)].md in the current folder. [(TODO)] stays a normal filename everywhere; Tag Fox can present it like a dedicated todo label.
                
      • 
                
    • 
                  Folder doc is for “what this folder is for” in markdown; keep agreed context beside the files it describes. Tag that doc (or any file) with [(active)], [(archived)], etc., and filter with the tag bar.
                
      • 
                
    • 
                  You can run a whole project from markdown notes + tags + Tree View without a proprietary database. Google Drive still lacks a decent native markdown editor in the browser — local editing in Tag Fox is one workaround.
                
      • 
                
    • 
                  If renaming folders on synced Drive proves flaky, fall back to tagging files only (or a metadata/readme at the folder root) and still navigate in tree mode.
                
      • 
              
    
            
    
            
    
              
      
                
    • 
                  Google Drive / OneDrive “streaming” (files appear in Explorer but download on demand): search and previews may work for placeholders, but renames, moves, and deep paths can fail or feel inconsistent. Full mirroring behaves more like normal disks.
                
      • 
                
    • 
                  Bracket tags on folders require renames on disk. Windows may block renames while something holds a handle (file open, terminal cwd, etc.). Tagging files remains reliable.
                
      • 
                
    • 
                  Google Docs shortcuts (.gdoc etc.) show one name in Drive on the web and another locally after tag edits — expect that mismatch.
                
      • 
                
    • 
                  Shared Workspace files / another person’s Drive trees may not open in the child window the same as your own; streaming vs mirrored shortcuts matters.
                
      • 
                
    • 
                  Everything 1.5 vs 1.4: advanced options and some query shapes behave differently over HTTP; prefer Everything 1.5+ when possible.
                
      • 
                
    • Everything must stay running and indexing; Tag Fox only talks to its HTTP API.
      • 
              
    
            
    
            
    
              
      
                
    1. 
                  Install Voidtools Everything and finish its initial index. Tag Fox does not replace it.
                
      2. 
                
    2. 
                  Everything 1.5 Alpha: HTTP is provided as a plugin. Install/enable the HTTP plugin, then Tools → Options → HTTP Server — turn the server on, bind address/port (e.g. 127.0.0.1:8080), optional username/password, apply.
                
      3. 
                
    3. 
                  Everything 1.4.x: HTTP is built-in under Tools → Options → HTTP Server. Enable it and note URL/port/auth. No 1.5 plugin step.
                
      4. 
                
    4. 
                  Without 1.5, use 1.4’s built-in HTTP. With 1.5, use the plugin workflow first — steps differ; Tag Fox’s URL field is the same idea afterward.
                
      5. 
                
    5. In the Tag Fox app folder: npm install then npm start (or your packaged build).
      6. 
                
    6. Open Settings, set Everything base URL to match the server, and HTTP auth if set.
      7. 
                
    7. Optional: set a starting folder with the breadcrumb or path editor. Bulk rename: check rows → Ctrl+H → preview → Rename.
